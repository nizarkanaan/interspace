# Controlled Editing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Generate bounded Python fixes, approve actual isolated checks, review and explicitly apply an exact tested diff, then exercise it with Snack Picker.

**Architecture:** Keep all model jobs text-only. Separate editing policy/candidate storage, OS-restricted processes, guarded source application, orchestration and UI. New versioned change runs coexist with legacy and read-only team runs.

**Tech Stack:** Existing Python 3.9+, Swift AppKit/WebKit shell, plain JavaScript/CSS; macOS system process restrictions and atomic exchange; no dependencies or HTTP service.

**Spec:** `docs/superpowers/specs/2026-11-11-controlled-editing-design.md`, approved by the user in this chat on 2026-11-11.

## Global Constraints

- Work on `interspace/controlled-editing` in the current checkout; retain task-desk commits; no merge or push.
- Sample Project stays read-only and is not accessed. Snack Picker is the only live write-test project.
- Task modes: `review` (missing field defaults here), `python_fix` (immutable). Existing saved records/approvals keep their meaning.
- New plan kind `change`, run format `change-v1`; no arbitrary model tools, shell commands, packages, network, renames, deletions, binaries or symlinks.
- Repeated roles allowed; disjoint Implementer paths; at least one Implementer/Tester/Reviewer; Tester after all Implementers; Reviewer covers every non-Reviewer assignment.
- At most eight `.py` write paths, 100,000 generated bytes per file and 200,000 total. Test paths below `tests/`; existing writes selected, new writes absent; at least one code and one test path.
- Preserve source-selection and positive editable specialist limits. Model calls: one planner, one per specialist and one synthesis, 240 seconds each, no retries. Test processes: exactly three maximum, 30 seconds and 100,000 combined output bytes each.
- Separate exact approvals for proposal generation, frozen-candidate checks, and final reviewed application. No automatic repair/resume/source writes after restart.
- Only app-owned copies execute. Read-only check tree, writable scratch, clean environment, no network/children/unrelated data; fail closed if restrictions unavailable.
- Source application needs supported same-filesystem atomic exchange/exclusive creation, displaced bytes retained, durable journal and conflict recovery; no destructive fallback.
- Follow light/dark, keyboard/narrow-layout conventions; reuse fixed scene artwork; rebuild only `dist/Interspace.app`.

## Review Focus

- A stale or switched task must not run checks or apply another task's diff: Task 3 backend and Task 4 delayed-response journeys.
- A test writes through a Data-volume alias or spawns another Python: Task 2 actual restriction canaries.
- A user edits a target between preflight and replacement: Task 1 injects that race and verifies displaced user bytes/recovery.
- An app quits between an external side effect and its saved completion: Tasks 1/3 journal recovery and reservation replay tests.
- Historical Snack Picker text says read-only while the current task permits a fix: Task 3 prompt/action authority regression without changing those documents.

### Task 1: Editing policy, candidate evidence and guarded source application

**Files:** Create `app/backend/changes.py`, `app/backend/change_apply.py`, `tests/test_changes.py`, `tests/test_change_apply.py`; extend `app/backend/sources.py` for the new manifest-backed format only.

**Interfaces:** `changes.make_plan(project, revision, goal, assignments, specialist_limit, task_id) -> dict`; `validate_plan(plan)`; `prepare(project, plan, storage) -> Path`; `load(run) -> dict`; `validate_record(record, run=None)`; `stage_candidate(run, record, assignment, result) -> dict`; `evidence(run, record) -> {id: text}`; `validate_result(run, record, assignment, result) -> dict`; `candidate_digest(run, record) -> str`; `artifact_id(record) -> str`; `check_current(project, run, record)`; `interrupt(record, stage, detail)`; `changes.TERMINAL`. `change_apply.apply(run, record, cancel, hook=None) -> dict` journals and returns application outcome, preserving source bytes; `recover(run, record) -> dict` only inspects an unfinished journal and never writes sources.

**Records:** Change runs retain common snapshot fields plus tasks/jobs/results/combined/limits/events, `candidate` (canonical replacements, hashes, diff, digest), `checks` (reservations/results), `test_approval`, and `application`. Assignment fields add `write_paths` (empty except Implementer); normalized roles are researcher/implementer/tester/reviewer. Implementer result uses ordinary report fields plus `files:[{path,content}]`; other roles return empty `files`. Evidence IDs are `original:<path>`, `candidate:<path>`, `check:baseline`, `check:regression`, `check:candidate`. Original source paths may be aliases only when unambiguous; never remap old IDs to candidate content.
